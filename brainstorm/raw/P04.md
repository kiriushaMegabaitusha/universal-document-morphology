## P04-1 — Slot-alphabet redundancy budget: an entropy metric for document channels

Participant: P04 | Stage: independent | Origin: AI-generated | Date: 2026-10-15

**Statement (idea).** Compute an information-theoretic efficiency profile for each of the 25 slot-coded systems — slot-wise entropy, conditional entropy given genre, and each slot's share of total redundancy — to convert the repo's unmeasured claim that official formats spend their bits on validity rather than comprehension into a number.

**Mechanism / rationale (idea).** A document format is a channel that encodes one event into a 14-position binary codeword; `requisites.csv` (225 rows) and `analysis/slot_matrix.csv` already contain the codewords, so entropy, conditional entropy by genre (epistolary vs normative), and per-slot redundancy decomposition are a small CPU computation with bootstrap over systems. If redundancy concentrates in S12 (authentication) and S14 (trace) while S6/S9/S11 carry little, the atlas's qualitative statement ("nothing is optimised for comprehension", `morphology.md` §5.5–§6) becomes a quantitative metrological result: the corpus spends its error-correction budget on forgery-resistance and audit, not on reader understanding.

**Assumptions.**
- (assumption) Slot presence/absence as hand-coded is a valid proxy for transmitted variety — the coding is a good-enough measurement of the code.
- (assumption) 25 systems is enough for stable entropy estimates despite the sparsity already documented in `analysis/findings.md` §4 (the JP = KE = HN 1.0 artifact).
- (assumption) Genre labels used for conditioning (epistolary/normative) are correct per system.

**Predicted observations (prediction).**
- Per-slot redundancy share ranks S12 and S14 above S6, S9, S11; S12's share is stable under leave-one-system-out resampling.
- H(slots | genre) is substantially below H(slots) — genre explains more variety than tradition, giving finding 3 an information-theoretic form.
- High-density regimes (Soviet bloc, mean 9.0 slots) show higher raw redundancy than low-density regimes (records/legal, 1.7) but not higher mutual information with system identity — density is mostly audit overhead.

**What would disconfirm it (prediction/falsifier).** The decomposition puts redundancy uniform across slots, or the structure is fully reproduced by coding density and sparsity under a permutation null (the metric would then only re-derive the caveats in `findings.md` §4); or H(slots | genre) ≥ H(slots), i.e., genre explains nothing measurable.

**Main feasibility risk.** Small-n bias: mutual-information estimators are biased upward at n = 25, so permutation nulls and bias-corrected estimators are mandatory; if permutation nulls swallow every effect, the metric has no signal at this sample size and the idea dies honestly. CPU cost is trivial.

**Repo connections.** `requisites.csv`; `analysis/slot_matrix.csv`, `analysis/slot_similarity.csv`; `analysis/findings.md` §1, §4, §7; `morphology.md` §1 (Ashby variety) and §6 ("efficiency would need a metric"); README "Honest gaps" ("'Efficiency' is measured nowhere in the standards").

**Verification (not already done).** The repo computes slot frequencies, Jaccard similarity, implication rules and keyword themes only — no entropy, mutual information or redundancy figure exists in any `.md` or `.py`; `analysis/recompute.py` rebuilds frequencies and Jaccard and checks them against prose.

## P04-2 — Morphology-as-factor parsing-cost benchmark (machine arm, format instead of register)

Participant: P04 | Stage: independent | Origin: AI-generated | Date: 2026-10-15

**Statement (idea).** Extend the existing machine arm from a register contrast to a morphology contrast: render one identical obligation in six corpus formats (DIN-5008 letter, ДСТУ наказ, GB/T 9704 公文, UN resolution, EU regulation, Francophone lettre administrative) and measure extraction accuracy, prompt-token cost and latency per format.

**Mechanism / rationale (idea).** `morphology.md` §6 names parsing cost and downstream error as candidate efficiency metrics and measures neither; the harness already exists (`experiment/machine_arm.py`, `analysis_core.py`, `check_stimuli.py`) and a full 12-model run cost $0.0314, so adding a format factor is an incremental stimuli extension rather than a new instrument. Holding obligation content and register constant while varying only the slot layout isolates layout-driven parsing cost — a direct, machine-only test of which morphology is the cheaper information channel, squarely in the "documents as machine-operable control records" framing of `morphology.md` §1 and finding 13c (Soviet automation-in-doctrine).

**Assumptions.**
- (assumption) Stimuli remain constructed (`verbatim: false`) and gated exactly as `check_stimuli.py` gates today: identical numeric-token sets across all renderings, independent answer key.
- (assumption) Machine parsing cost is a meaningful channel-efficiency proxy for this project (it measures machine legibility, never human comprehension — same caveat as the existing arm).
- (assumption) Register can be held constant while layout varies; format differs in more than layout, so the manipulation must be built as "same wording, different slot geometry" or the contrast is confounded.

**Predicted observations (prediction).**
- Accuracy stays at ceiling while token cost and latency differ measurably by format — the signal lives in cost, not accuracy (the existing arm already found documents machine-legible in both registers).
- Formats with dense identifier/trace heads (GB/T 版头, ДСТУ requisites) cost more input tokens per extracted fact but not more errors; sparse formats (DIN letter) cost least.

**What would disconfirm it (prediction/falsifier).** No cost or latency differences across formats at fixed content and fixed register, or differences vanish after normalising by raw prompt length — i.e., the effect is verbosity, not morphology.

**Main feasibility risk.** The ceiling problem documented in `experiment/README.md` (6 of 12 readers at 100% on v2) could mask everything: mitigate by pre-selecting the readers with demonstrated headroom (llama-3.2-1b, llama-3.1-8b) and keeping the harder inference items. Secondary risk: manipulation confound (format ≠ layout only). **Flag: any extension of this benchmark to human readers — ethics review required.**

**Repo connections.** `experiment/machine_arm.py`, `experiment/stimuli.json`, `experiment/check_stimuli.py`, `experiment/results/RESULTS.md`, `experiment/README.md` (ceiling finding); `morphology.md` §6; README "Honest gaps" (efficiency test half-run).

## P04-3 — Within-standard revision diffing: a time series of what standardisers actually change

Participant: P04 | Stage: independent | Origin: AI-generated | Date: 2026-10-15

**Statement (idea).** Treat the layer-1 standards as versioned artefacts (DIN 5008 across its post-1949 revisions, ДСТУ 4163:2003 → 4163:2020, ГОСТ 6.38-90 → ГОСТ Р 7.0.97-2016, GB/T 9704 editions) and diff their requisite inventories across editions to measure per-decade slot accretion and deletion rates.

**Mechanism / rationale (idea).** The repo's diachrony is cross-sectional — one approximate anchor year per system in era bins (`analysis/qualitative_analysis.md` §4) — so it cannot separate "modern documents carry identifiers" from "modern standard revisions add identifiers"; diffing editions of the same standard gives a true longitudinal series of standardisers' change decisions, with each standard serving as its own control. In metrological terms the measured object shifts from the document to the standard, which is where the ISO/DIN/GOST tradition actually operates: rules accrete, or they don't.

**Assumptions.**
- (assumption) Superseded editions are retrievable in full text (some are archived, some sold by standards bodies — the repo has hit structurally blocked sources before).
- (assumption) Each edition's requisite inventory maps onto the closed 14-slot vocabulary using the same coding rules as `requisites.csv`.
- (assumption) At least three systems have three or more retrievable editions each; below that the series is anecdotal.

**Predicted observations (prediction).**
- Net accretion, not pruning: revisions add S2/S14-family requisites (registration, identifier, receipt) and never delete S12 — the "modernity is the identifier" reading of `qualitative_analysis.md` §4 reappears within standards, not just between eras.
- The four-addressee rule (`diversity.md` §13e) survives every ДСТУ edition unchanged while additive requisites accumulate around it — fossil rules persist.
- Per-decade change rate is low (order of ~2 slot deltas per decade) — standards are path-dependent.

**What would disconfirm it (prediction/falsifier).** Edition diffs show large bidirectional churn, or S2/S14 share stays flat within standards, or any apparent accretion is fully explained by changes in document-type coverage (new editions covering new document types) rather than changes to existing types.

**Main feasibility risk.** Retrieval of obsoleted standards is the hard gate — often paywalled or mirrored unreliably (cf. the RU blocked source in `cases/ru.md` and the byte-identical Gulf mirror lesson, `diversity.md` §12b); with few editions per standard, inference is weak; diffing is manual labour for one researcher. CPU cost trivial.

**Repo connections.** `STANDARDS.md` layer 1 (DIN 5008 "revised since 1949", ДСТУ 4163 2003/2020, ГОСТ Р 7.0.97-2016); `analysis/qualitative_analysis.md` §4; `diversity.md` §13d–§13e; README "Honest gaps" (diachronic dating is an approximate regime-anchor year); `requisites.csv` coding scheme as the diff vocabulary.

**Verification (not already done).** No revision-level or edition-level data exists anywhere: diachrony uses one anchor year per system, and no file in `analysis/` compares editions of any standard.

## P04-4 — Uncertainty budget for the coding instrument (measurement-system analysis of the atlas)

Participant: P04 | Stage: independent | Origin: AI-generated | Date: 2026-10-15

**Statement (idea).** Run a blinded re-coding study of a stratified subsample of case files — a second human coder and/or independent LLM coders — and propagate the observed disagreement through `analysis/recompute.py` so that every headline finding carries a measurement-uncertainty interval instead of a point value.

**Mechanism / rationale (idea).** The atlas's quantitative findings are outputs of a measuring instrument (the 14-slot coding scheme plus keyword theme coding), and the instrument's repeatability is unquantified: README "Honest gaps" records "no inter-rater kappa", and `qualitative_analysis.md` §6 repeats it. A metrological treatment — reproducibility across coders, repeatability across coder × file, plus a vocabulary type-1 error rate for ambiguous slots — turns each headline number (S12 = 17/25, S6 ⊥ S9, the Jaccard pairs) into a distribution by re-running the recompute pipeline on resampled codings. This both fills an acknowledged gap and extends it: the repo flags missing kappa but never propagates coding error into the findings themselves.

**Assumptions.**
- (assumption) One colleague or a set of independent, blind LLM coder runs (documented model and settings) can be mobilised by a solo researcher; coder-agreement work is analysis, not data collected from people — **no ethics review required** for the coding itself.
- (assumption) Coders can be blinded to the original coding and to the headline findings.
- (assumption) Bootstrapping codings with empirical agreement rates is a defensible uncertainty model (agreement as proxy for true error).

**Predicted observations (prediction).**
- Agreement is high on stem slots (S3, S5, S12) and low on the boundary slots (S9 vs S10/S11, S14 vs S1) — ambiguity concentrates where the model's interesting claims are.
- Headline findings survive: S12 remains the modal slot and S6 ⊥ S9 holds in ≥ 95% of resampled codings; the JP = KE = HN similarity pairs do not survive, confirming them as artifacts.
- Theme-coding kappa (the acknowledged gap) lands well below slot-coding kappa.

**What would disconfirm it (prediction/falsifier).** Resampled codings flip the headline findings in more than 5% of draws — i.e., the conclusions sit inside the project's own measurement error; that result would falsify the robustness prediction while itself being a publishable metrological finding.

**Main feasibility risk.** Mobilising and blinding a second coder while working alone; and shared bias if the original coding was agent-assisted and the LLM coders share a family — reproducibility must be reported separately for human vs machine coders, or agreement will be inflated.

**Repo connections.** README "Honest gaps" + "The gate" section; `check_claims.py`; `analysis/recompute.py` (checks figure drift, not coding uncertainty); `analysis/findings.md` §4, §7; `analysis/qualitative_analysis.md` §6; `requisites.csv`.

## P04-5 — Identifier channel capacity: metadata bits per character in slot S2

Participant: P04 | Stage: independent | Origin: AI-generated | Date: 2026-10-15

**Statement (idea).** Quantify S2 as an information channel: encode each corpus identifier grammar (UN symbol, ОКУД/НК 010 eight-digit codes, GB/T 版头 fields, DIN reference line, UAE naming discipline) in a fixed field dictionary, then measure metadata bits carried per character and the error rate of decoding document metadata from the identifier string alone.

**Mechanism / rationale (idea).** `morphology.md` §5.4 claims identifier formality is a spectrum and calls the Chinese 版头 the most "database-like" block; `diversity.md` §13b calls ОКУД a schema with a check digit — both are qualitative judgements. Fixing a field dictionary (organ, type, series, number, year, secrecy, copy, check digit) lets every identifier be scored as a code: capacity = Σ log2(field alphabet size), efficiency = capacity ÷ string length, plus a mechanical decoding task giving an empirical error rate. This is a literal measurement of how efficiently each tradition packs retrievability into its identifier — the S2 claim made falsifiable.

**Assumptions.**
- (assumption) Identifier exemplars in `cases/` and `sources/` are representative and can be supplemented to ≥ 10 per system from public documents without new privileged access.
- (assumption) One field dictionary can be applied across traditions without structurally favouring the decomposed formats.
- (assumption) Characters are the right length measure despite mixed scripts (Latin/Cyrillic/Han/Arabic/Thai per `analysis/findings.md` §6) — or a script-normalised alternative is fixed in advance.

**Predicted observations (prediction).**
- Decomposed identifiers (UN symbol, ОКУД) deliver at least about twice the metadata bits per character of opaque serials (DIN-style) and decode with near-zero error, while opaque identifiers force the reader into S1/S3 to recover type and organ — low S2 capacity pushes cost into other slots.
- Bits per character in S2 tracks the corpus's own qualitative ordering of "database-likeness" (UN / CN / SU high, DIN low), so the metric reproduces, rather than contradicts, the existing qualitative ranking.

**What would disconfirm it (prediction/falsifier).** Bits per character fails to separate the identifier forms, or separation disappears once length is normalised per script, or decoding error is uniform across forms — any of which would show that "identifier formality" is a qualitative impression with no measurable channel consequence.

**Main feasibility risk.** Small exemplar counts per system; the field dictionary is itself a coding scheme whose subjectivity must be handled by preregistering it before computing anything; length-normalisation choices can drive the result if fixed after seeing data.

**Repo connections.** `morphology.md` §2 (S2 definition) and §5.4; `diversity.md` §7 (system-assigned identifiers) and §13b (ОКУД check digit); `analysis/findings.md` §1 (S2 at 11/25); `STANDARDS.md` layer 3 (UN symbol grammar); `analysis/slot_matrix.csv`.

**Verification (not already done).** Identifier formality is discussed qualitatively only; no bits, length, capacity or decoding measurement exists in `analysis/` or anywhere else in the repo.

## P04-6 — The five kinds of document law as a feature matrix: partition or mixture?

Participant: P04 | Stage: independent | Origin: AI-generated | Date: 2026-10-15

**Statement (idea).** Operationalise the kinds of document law (layout, formulas, naming, function, plus the trace / access / persistence regime dimensions) as rule-based per-system indicators over all 28 systems, build the resulting feature matrix inside `analysis/`, and test whether the typology is an exclusive partition or a continuous mixture.

**Mechanism / rationale (idea).** README "Honest gaps" states that the regime classes are "hand-assigned and not derivable from the CSVs", so `recompute.py` checks everything except the typology — the classification sitting on top of the verified pipeline is the one part nobody can recheck. Each kind has observable indicators already described case-by-case (page-format standard with mandatory geometry; permitted-phrase banks; reference discipline; statutory type classifier; statutory trace/access/appraisal clauses), so a stated decision rule per indicator yields a 28 × k binary matrix that the gate can validate like any other artefact; association/clustering on it then asks whether systems occupy clean kinds or mixtures — and `diversity.md` §13a (the Soviet bloc legislating all three layers at once) already predicts mixture.

**Assumptions.**
- (assumption) Every indicator is decidable from existing case files without new sources.
- (assumption) A mixture outcome is the more informative result — it reframes the typology as a feature space rather than breaking it.
- (assumption) Decision rules can be written tightly enough that re-coding is mechanical (the same requirement P04-4 measures).

**Predicted observations (prediction).**
- No system carries a unique kind-label: at least two kinds co-occur in at least a third of systems (Soviet = layout + function + workflow; Francophone = formulas plus layout; UAE = naming plus layout), i.e., the typology is a mixture, not a partition.
- The regime dimensions (trace, access, persistence) load on a different axis from the page-level kinds — two families of properties, not five peers.
- Making the classes derivable changes at least one assignment currently used in the coding-density table (`analysis/findings.md` §3), exposing a hand-assignment as an assumption.

**What would disconfirm it (prediction/falsifier).** Systems fall into mutually exclusive kinds with sparse, non-overlapping columns — the partition holds as typologised, and the current hand-assignment is validated.

**Main feasibility risk.** Indicator coding drifts back into subjectivity — the very defect the idea targets — unless each decision rule is written and frozen before coding; some kinds (formulas) are documented for only a few systems, giving sparse columns and unstable association estimates.

**Repo connections.** README "Honest gaps" (hand-assigned regime classes not derivable from CSVs); `analysis/recompute.py` (scope limits); `analysis/findings.md` §3 (coding density by regime class); `diversity.md` §11b (formulas), §12a (naming), §12d (access), §13a (three layers at once); `EXECUTIVE_SUMMARY.md` "catalogue of kinds of document law".
