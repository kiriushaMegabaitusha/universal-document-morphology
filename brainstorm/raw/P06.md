## P06-1 — Measure coding reliability once, then propagate the measured error into every headline figure

**Participant: P06 | Stage: independent | Origin: AI-generated | Date: 2026-10-15**

**Statement (idea).** Blindly re-code a stratified random subsample of all four hand-coded layers of the atlas — slot mappings in `requisites.csv`, keyword themes, era anchors, regime classes — with a frozen codebook, quantify agreement (κ / exact agreement), and then propagate the measured error rates through a `recompute.py`-style resimulation to report which headline findings survive plausible mis-coding.

**Mechanism/rationale (idea).** The repo's gate checks that quoted figures match the data, but nothing checks that the data match a defensible second reading: the README's honest gaps state theme coding has "no inter-rater kappa", and `analysis/qualitative_analysis.md` §6 states themes are "not double-coded" and era anchors are approximate. Reliability that is never measured cannot be propagated, so every published figure (17/25, 8/10, the diachronic shares) is reported as if error-free; sampling error from coding error is a different quantity and is currently unquantified. Measuring it once and re-running the analysis under perturbed codings converts a stylistic caveat into a bounded uncertainty on each claim.

**Novelty check (fact).** Grep across root, `analysis/` and `experiment/` (excluding `brainstorm/`) finds "kappa / inter-rater / double-coded" only as *admissions* in `README.md`, `EXECUTIVE_SUMMARY.md` ("a two-coder thematic pass" listed under "What remains") and `analysis/qualitative_analysis.md` §6 — no reliability measurement exists, and `analysis/recompute.py` checks figure-to-data consistency only, never data-to-alternative-coding sensitivity. The theme double-coding pass is *named* as remaining work; the extension here (all four layers, plus error propagation into the findings) is not.

**Assumptions.**
- *assumption:* a second coding pass is possible for a sole researcher; the primary route is an LLM second coder at temperature 0 with a codebook frozen before seeing the originals, with the researcher auditing all disagreements — an assumption that machine-coded agreement bounds human inter-rater agreement, stated as untested.
- *assumption:* coding errors are approximately independent across rows conditional on slot/type; if errors cluster by tradition, clustering-robust resampling is required instead of row-level perturbation.
- *assumption:* the four layers can be re-coded from the case files and `requisites.csv` alone, without new source retrieval.

**Predicted observations.**
- *prediction:* agreement is highest for stem slots (S3, S5, S12) and lowest for optional/sparse slots (S9, S11, S14) and for the keyword themes (moderate κ), because stem slots are textually explicit and themes are diffuse.
- *prediction:* the authentication census (17/25) and the fork survive perturbation at the measured error rate, while the diachronic bins (n = 6–10 per `qualitative_analysis.md` §4) do not — small-bin shares move under a single recode.
- *prediction:* at least one figure quoted in `EXECUTIVE_SUMMARY.md` shifts outside the tolerance `recompute.py` currently enforces, once plausible coding error is simulated.

**Disconfirming observation (prediction).** The idea is disconfirmed if agreement is high on *all four* layers **and** no headline figure moves under simulated error rates at the measured κ — in which case the exercise yields a documented "coding error does not threaten any finding" result, which is a null worth having but not a new analysis program.

**Main feasibility risk (assumption).** An LLM second coder is not an independent human rater, so the resulting κ describes a machine–human comparison whose relation to human–human κ is itself an assumption; the cheaper risk is that the deliverable collapses into the already-planned "two-coder thematic pass".

**Ethics status (fact).** LLM-coder route: ethics review not required. Optional variant with a recruited human second coder: **ethics review required**.

## P06-2 — Exact null-model test: is the "formal negation" a structural law or a sparse-sample absence?

**Participant: P06 | Stage: independent | Origin: AI-generated | Date: 2026-10-15**

**Statement (idea).** Convert the atlas's perfect structural rules (S9 ⊥ S4/S6/S7/S8/S10/S14 and the 1.00 implication rules S6⇒S12, S8⇒S12) from census statements into population inferences, using exact enumeration/permutation nulls on the 25-system slot matrix with FDR control, plus a sample-size target for how many further systems each per-edge claim needs before it is informative.

**Mechanism/rationale (idea).** "Never co-occurs in our data" is a fact about 25 systems; whether it would hold in the next system is a sampling question, and with the printed marginals some of these perfect patterns are exactly what chance would produce. Worked example (hand-derived from `analysis/findings.md` §1–§2 — S6 = 8/25, S9 = 2/25; **re-derive in code at run time**): under independent placement, P(the two S9 systems both fall outside the eight S6 systems) = C(17,2)/C(25,2) = 136/300 ≈ 0.45 — the single edge the prose calls "the clearest single structural finding" is, alone, not unlikely. The right test is therefore on the *joint* pattern (no S9 system carries any of the six partner slots), which is enumerable exactly over all C(25,2) = 300 placements of the S9 vector, alongside the per-edge p-values and a tradition-clustered null.

**Novelty check (fact).** Grep for hypergeometric/permutation/cross-validation across root, `analysis/` and `experiment/` finds resampling code only inside `experiment/` (sign-flip tests on item-level differences, bootstrap CIs) — the atlas-side analyses (`findings.md`, `qualitative_analysis.md`, `recompute.py`) contain no null model, no p-values and no power analysis for any structural rule.

**Assumptions.**
- *assumption:* the 25 slot-coded systems can be treated as exchangeable draws from a defined population of written official-document regimes under the null; because traditions cluster, a second, block-permuted null (permute within tradition families) is required and may change conclusions.
- *assumption:* slot coding is treated as fixed (no coding error) in this idea; P06-1 addresses that layer separately, and the two interact.
- *assumption:* the marginal counts printed in `findings.md` are the analysis inputs; if system-level rows in `requisites.csv` disagree with them, the exact test must be run from the raw matrix.

**Predicted observations.**
- *prediction:* per-edge, S9 ⊥ S6 will not reject independence (p ≈ 0.45 by the worked example), while at least one high-support positive rule (e.g. S6 ⇒ S12, support 8 of 8 against a 17/25 marginal) will reject even after FDR correction.
- *prediction:* the *joint* negation pattern will reject (the six partner slots jointly cover most of the 25 systems, so very few S9 placements avoid all of them), so the correct regrading is: the fork is supported as a joint pattern, not as six independent pieces of evidence.
- *prediction:* a computed power curve will show that several per-edge claims cannot reach 0.80 power at any plausible corpus size, i.e. some rules are currently untestable rather than confirmed.

**Disconfirming observation (prediction).** The idea's reading is disconfirmed if the exact joint test fails to reject (many systems genuinely lack all six partner slots), which would strip the fork of its evidential base and force it to be reported as descriptive only — or if the tradition-blocked null makes the pattern *more* surprising than the unblocked one, reversing the expected per-edge ranking.

**Main feasibility risk (assumption).** At n = 25 the permutation p-value has a floor set by the enumeration (300 placements → min p ≈ 0.003), and conclusions are sensitive to the choice of null (independent vs tradition-blocked); the null choice must be pre-specified or the result will look like a analyst-degrees-of-freedom problem.

**Ethics status (fact).** Not applicable — no human participants.

**Repo connections (fact).** `README.md` headline findings 1–2, `morphology.md` §3 and §5.2, `analysis/findings.md` §2, `analysis/qualitative_analysis.md` §1 (implication rules + negative rule), `analysis/slot_matrix.csv`, `analysis/recompute.py`.

## P06-3 — Turn "genre, not nation" into a measured variance partition with uncertainty

**Participant: P06 | Stage: independent | Origin: AI-generated | Date: 2026-10-15**

**Statement (idea).** Quantify headline finding 3 as an effect size: build a system × genre slot matrix (each system's epistolary exemplar and normative exemplar, coded from existing case files), partition cross-system variation in slot presence between genre, tradition family and residual — permutation-based variance partition (PERMANOVA on Jaccard distances) plus a hierarchical logistic model with tradition as a grouping factor — and report R² with bootstrap confidence intervals.

**Mechanism/rationale (idea).** "Genre, not nation, is the main axis of variation" is currently a qualitative reading of the convergence matrices and of a clustering that "collapses to one trunk" (`findings.md` §4); without a partition and an interval, it cannot lose: any pairwise pattern can be narrated either way. A partition forces the two live explanations (deep-grammar-vs-tradition, genre-vs-nation) to compete on the same data with a pre-stated statistic, and a null result — tradition explaining as much as genre — would be a substantive challenge to a headline claim rather than a rhetorical preference.

**Novelty check (fact).** Grep for PERMANOVA / variance partition / effect size / mixed-effects across root, `analysis/` and `experiment/` returns only experiment-side SESOI language; `findings.md` §4 reports Jaccard pairs and a verbal clustering reading, `qualitative_analysis.md` §1 reports implication rules — no partition of variance between genre and tradition exists anywhere in the repo.

**Assumptions.**
- *assumption:* genre can be coded at the unit used by `requisites.csv` — either rows already carry a document-type tag, or a genre column must be added by coding two exemplars per system from `cases/` (both genres are documented for several systems, e.g. UA letter vs наказ, CN 信函 vs 命令, Bénin lettre vs note per `diversity.md` §12c). - *assumption:* tradition families (Anglophone/Germanic/Sinosphere/Francophone/Soviet/Islamicate/…) can be assigned per system from the case files without new sources; these labels are analyst-assigned and inherit the same reliability caveat as P06-1.
- *assumption:* Jaccard distance on binary slot presence is an acceptable dissimilarity for the partition; alternative codings (presence/obligatory/optional as ordinal) must be pre-specified, not chosen after seeing results.

**Predicted observations.**
- *prediction:* genre carries the larger share of explained variance, but the interval is wide at ≈28 systems × 2 genres, and the tradition term is non-zero — the honest result is "genre > tradition, both small, both uncertain".
- *prediction:* within-system genre pairs show the largest slot deltas concentrated exactly on S6/S9 (the fork), while tradition explains the residual surface slots (S4/S12 form, S14 density) — i.e. the two axes are not rivals but act on different slot subsets.

**Disconfirming observation (prediction).** The idea's core prediction is disconfirmed if tradition family explains as much or more variance than genre, or if the genre term vanishes when the analysis is restricted to within-system pairs — either outcome would show the current genre-vs-nation claim is an artefact of between-system coding and would require rewriting `README.md` headline 3.

**Main feasibility risk (assumption).** The genre column has to be coded by hand for ~56 rows from prose case files, so coder judgement (and P06-1's reliability question) re-enters the measurement; with ~28 independent units the permutation distribution is coarse and the model must stay simple (two terms, no interactions).

## P06-4 — Universality as a prevalence estimate: sampling frame, intervals, leave-one-tranche-out, and a committed hold-out prediction

**Mechanism/rationale (idea).** The 28 systems are a purposive sample selected partly by *retrievability of a standard*, which is correlated with the very property being claimed (a codified document regime), so 17/25 read as a law of nature when it is a sample proportion: hand-computed Wilson interval for 17/25 is ≈ [0.48, 0.83] (**re-derive in code at run time**). Intervals plus leave-one-out show whether a headline is robust or is one tranche's signature; a committed, pre-coded prediction converts the atlas from post-hoc description into a genuine out-of-sample test of the deep grammar.

**Novelty check (fact).** Grep for confidence intervals / Wilson / beta-binomial / cross-validation / leave-one-out / sampling frame across root, `analysis/` and `experiment/` returns nothing on the atlas side (only experiment-side bootstrap CIs); no slot prevalence is quoted with an interval anywhere, `recompute.py` rebuilds figures without uncertainty, and the RU column is explicitly open (`cases/ru.md`, README honest gaps).

- *assumption:* systems are not independent draws (tradition clustering), so intervals must be reported both naively and clustered, and the clustered version will be wider.
- *assumption:* the prospective component needs one genuinely uncoded system; `diversity.md` §9 names candidates (Central Asia, more of Africa, Indigenous North America beyond wampum), and resolution of `cases/ru.md` is an alternative — retrieval work, no new data collection.

**Main feasibility risk (assumption).** The sampling frame is the weakest link: any frame is contestable, so a reviewer can always claim a different population; the mitigation is to report the estimate under two or three pre-stated frames rather than defend one.

## P06-5 — Is the 10 pp SESOI even attainable? Ceiling-constrained power plus item calibration on an expanded machine panel — before any human is seen

**Participant: P06 | Stage: independent | Origin: AI-generated | Date: 2026-10-15**

**Statement (idea).** Quantify how much of the registered 10 pp SESOI is attainable as a function of baseline accuracy (at baseline b the largest possible plain advantage is 1−b), re-derive the design's power surface over (baseline, effect) rather than at the single assumed baseline, and calibrate all 18 items' difficulty and discrimination on an expanded machine reader panel (the 12-model arm cost $0.0314, so a 60–100 model panel is dollars) so the human instrument is retargeted before recruitment starts.

**Mechanism/rationale (idea).** `experiment/simulate_data.py` fixes `base = 0.72 − effect_pp/2`, so the headline power figures (0.92 at N = 24, 0.98 at N = 36) are conditional on a ~67–72 % baseline, while the machine arm observed 0.926–0.928 and 6 of 12 readers hit 100 %; if human baseline is ≥0.90, a 10 pp advantage is impossible by construction, the "supported" branch of the decision rule becomes unreachable, and TOST will declare the effect "falsified" even when plain genuinely helps — ceiling converts a real small advantage into a guaranteed null verdict. Calibrating item difficulty on a wider machine panel (Rasch/2PL-style, family-clustered) before recruitment gives a quantitative basis for hardening the item set while everything is still pre-data, so no post-collection deviation is needed.

**Novelty check (fact).** Grep for IRT/difficulty calibration/baseline-sensitivity across root, `analysis/` and `experiment/` finds none: `simulate_data.py` uses one fixed base (line 61), the power table in `PREREGISTRATION.md` §7 reports three effect sizes at that base only, and the ceiling is noted qualitatively in `experiment/README.md` and `README.md` but never converted into attainable-effect or verdict-robustness terms. The machine arm has been run with 12 registered models only.

**Assumptions.**
- *assumption:* item difficulty ordering is sufficiently invariant between machine readers and humans to guide item selection — explicitly untested, and the repo itself insists the machine arm measures machine legibility, never human comprehension; this is the load-bearing assumption and must be stated as such.
- *assumption:* a 60–100 model panel is affordable and adds effective information (many models are correlated families, so effective n is much smaller than raw count; family-clustered calibration required).
- *assumption:* recalibration happens pre-collection, so the pre-registration can absorb it as a documented pre-data revision (precedent exists: Revision 1 in `DEVIATIONS.md`).

**Predicted observations.**
- *prediction:* the calibrated item set shows most extraction items at ceiling-difficulty with discrimination near zero, and only the v2 reasoning items (D2-Q3, D5-Q3 type) with usable targeting — i.e. the human arm's usable item count is well below 18.
- *prediction:* the re-derived power surface shows the registered 0.98 at N = 36 holds only for baselines ≲0.80; at baseline ≥0.90 the attainable effect is <10 pp, so the pre-registered verdict distribution shifts toward "falsified"/"inconclusive" regardless of the true register effect.
- *prediction:* expanding the panel reproduces the ordering of item difficulties rather than adding new easy items, supporting the (assumed) invariance enough to justify item selection.

**Disconfirming observation (prediction).** Disconfirmed if the power re-derivation shows the decision rule's verdict is stable across baselines 0.70–0.95 (i.e. ceiling does not change the conclusion), or if the expanded machine panel yields difficulty estimates that fail to predict even the machine panel's own hold-out models — in which case calibration adds nothing and the ceiling should simply be reported as a limitation, as the repo already does.

**Main feasibility risk (assumption).** Machine difficulty may be a poor proxy for human difficulty (the repo's own limitation 6), and model-family correlation may leave too little effective n for stable calibration; both must be reported, and any pilot run on *new human participants* to validate the proxy would require **ethics review required** before it could be used.

**Ethics status (fact).** Machine-panel work: ethics review not applicable. Any human pilot used to validate the machine-to-human proxy: **ethics review required**. Running the already-built human arm itself remains under its existing recruitment plan.

**Repo connections (fact).** `experiment/PREREGISTRATION.md` §6 (decision rule), §7 (power table, SESOI), §10 limitations 3 and 7, `experiment/simulate_data.py` line 61, `experiment/README.md` (ceiling paragraph), `experiment/results/RESULTS.md`, `experiment/DEVIATIONS.md`, `morphology.md` §5–§6 (finding 5).
