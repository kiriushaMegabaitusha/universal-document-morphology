**What would disconfirm it.** (a) Both bounds of every pre-listed claim coincide with the

## P11-2 — Sensitivity gate before any register null: give the TOST branch something to fail against

**Statement (one sentence).** Pre-register, as a pre-data revision with the same standing as
v1→v2, a sensitivity gate for the finding-5 instrument — a positive control with a guaranteed
≥SESOI effect (answer-bearing content corrupted vs size-matched intact sham) plus a
document-absent floor, run on the frozen machine panel before any recruitment — under the rule
that no equivalence/null verdict about register, *including the "no detectable register effect"
already printed in README v1.1/v1.2*, may be reported unless the instrument demonstrates
≥10 pp dynamic range on the same items, failing which the machine null is downgraded to an
instrument-insensitivity note and the human arm stays paused.

**Mechanism / rationale.** Ceiling converts into a positive equivalence verdict: at ~100%
accuracy both registers score identically, the preregistered TOST rejects ±10 pp, and the
decision rule returns "falsified — no decision-relevant difference" *because the instrument is
blind*, not because formality is harmless — v1 hit ceiling for 9/12 readers, v2 still near
ceiling for 6/12, and evidence check E03 located a prior documented register null on reading
times (SFB 1412) plus direct evidence that machine-panel item calibration does not transfer to
human difficulty (P06-5, challenge-located), so the most likely human outcome is a null whose
interpretation rests entirely on a sensitivity the preregistration establishes only by
simulation (`simulate_data.py`), never empirically. A known-effect control reuses the existing
harness at the demonstrated cost scale ($0.0314 per 864-call arm run) and gives the equivalence
branch a pre-committed failure condition instead of an unfalsifiable confidence statement.

**Assumptions.** `machine_arm.py`, `stimuli.json` v2 and `analysis_core.py` are reusable with
item variants only; control design and thresholds are frozen before any run; the machine panel
stays frozen (12 registered models + the named expansion); no human data before the P03-1
ethics gate — the gate's purpose is precisely to be passed *before* participants are spent;
a pre-data revision has precedent (`DEVIATIONS.md`, Revision 1).

**Predicted observations.** Most likely: the gate fails for the near-ceiling half of the panel —
either the corrupted-content delta is < 10 pp (items answerable without the document: the floor
control fires) or it passes only on models that were never at risk — so the registered
instrument cannot support its equivalence branch, the README/EXECUTIVE_SUMMARY line is
downgraded before v1.3, and the human arm is redesigned or dropped rather than run at a
baseline where 1 − b < SESOI for most of the sample. The passing outcome (controls clear on all
panel members) is equally informative: the register null becomes interpretable as a scoped
equivalence, and the artefact story closes positively.

**What would disconfirm it.** Controls show ≥10 pp separation with a working document-absent
floor for the whole frozen panel *before* recruitment → sensitivity demonstrated, gate passed,
null interpretable. Also disconfirming the artefact reading: if the control proves
non-representative of the register contrast (corruption measures gross damage, register
measures subtle cost) — then the gate is invalid, not passed, and must be redesigned; the
pre-registration must say this in advance rather than after results.

**Main feasibility risk.** The rubber-stamp failure: a corruption control proves dynamic range
for gross damage, which is necessary but not sufficient for a 10 pp register-shaped effect —
mitigate by pre-registering the gate's scope claim as "sufficient condition, not necessary",
and by computing per-model ceiling-constrained attainable bounds (1 − baseline) so uninformative
panel members are named *before* any register statistic exists (E03 found no prior derivation of
this bound, but also located direct evidence that machine→human calibration transfer is
contested — so bounds stay within-panel and are never extrapolated to humans).

**Repo connections.** `experiment/PREREGISTRATION.md` (locked TOST ±10 pp, H1 decision rule,
`simulate_data.py` power table), `experiment/DEVIATIONS.md` (Revision 1 precedent),
`experiment/check_stimuli.py` (checks surface-complexity proxies only — it never checks that
the *outcome* responds), `experiment/machine_arm.py`, README v1.1/v1.2 lines reporting the
machine null, `brainstorm/raw/evidence_E03.md`.

**responds to:** P06-5 challenge-located (E03: machine-panel item calibration ≠ human
difficulty — this gates on within-instrument controls instead of calibration transfer) +
